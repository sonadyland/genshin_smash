# 移动端适配

沿用 React、TypeScript、Vite 和 Canvas，移动端与桌面端共用同一套角色、战斗模拟、升级和动画数据。触屏完整覆盖秘境生存和单人试炼；本地双人保留原键盘 P2 操作，当前触屏控制 P1，不提供双套手机触控面板。

## 进入游戏与横屏布局

`useMobileEnvironment` 结合触点／粗指针能力与窗口短边识别移动环境，不依赖单一的横向宽度断点。大厅的“操作方式”还可以手动选择自动识别、触屏按键或键盘，选择保存到本地。存储不可用时保持本次页面会话可用。

点击开始时，在同一个用户手势中解锁声音并尝试全屏；实际进入全屏后，浏览器支持时尝试 `screen.orientation.lock('landscape')`。锁定失败不会阻止游戏界面打开。竖屏进入战斗时立即暂停，显示“请横持设备”，横持后仍需点击继续。浏览器切后台、窗口失焦或退出已进入的全屏时也会暂停并清除触控状态，不会自动恢复战斗。

普通网页不能承诺强制旋转所有手机。全屏请求依赖用户激活并可能被拒绝；方向锁定有平台限制，通常要求移动设备与全屏环境。因此竖屏提示和手动横持属于完整支持路径。[MDN 全屏 API](https://developer.mozilla.org/en-US/docs/Web/API/Element/requestFullscreen)、[MDN 方向锁定](https://developer.mozilla.org/en-US/docs/Web/API/ScreenOrientation/lock)

进入战斗后，场景容器覆盖可用视口，左右控制器和 HUD 直接叠加在场景表层，不另划底部操作栏。Canvas 使用 `object-fit: contain` 保留完整 16:9 游戏视野，不拉伸角色或裁切碰撞区域；超宽视口的余量由场景背景延展填充。按钮依据安全区内缩，避开刘海与系统手势区域。[MDN 安全区环境变量](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Values/env)

大厅压缩宣传与角色信息，仍可触摸选择角色、难度、模式和开始游戏。生存模式的血量、经验和计时叠加到顶部；升级弹窗横排三张紧凑卡片，分支选择横排两张。单人试炼的双方状态卡移至顶部左右，计时保留在中央，避免原底部 HUD 被触控按键遮住；桌面模式保留原 HUD。暂停、结算和设置面板在短屏中允许滚动，保留键盘焦点限制与原有桌面布局。

## 触控输入与按键设置

左侧固定十字键提供左右移动、下落／穿过软平台，以及可关闭的上键跳跃。左右之间可连续滑动切换；从左右格擦入上格不会起跳。右侧六键分别是普攻、重击、元素技能、战技、闪避和跳跃。默认大小为 60 CSS 像素，窄／矮视口会限制实际尺寸和左右内移，避免两侧按钮互相覆盖。

`BattleInput` 将键盘与触控转换为相同的逻辑动作。每根手指按 `pointerId` 独立捕获和释放，多根手指可以同时移动、起跳、攻击；方向键上跳与右侧跳跃各有独立来源。攻击和技能只读取按下边沿，持续按住不会在动作结束或技能冷却后自动重复释放。角色限制仍由战斗引擎即时校验，触控按钮的冷却与可用状态只作提示。魈在地面显示“空中”，起跳后可立即接元素坠击，无需等待 HUD 刷新。

使用 `pointerup`、`pointercancel`、`lostpointercapture` 和组件卸载清理按键；暂停、升级和其他模态切换清除输入，旧手指必须重新松开／按下才能产生新操作，避免返回战斗后黏键或补发攻击。操作区域使用 `touch-action: none`，普通页面按钮保留适合点击的触屏行为。[MDN Pointer Events](https://developer.mozilla.org/en-US/docs/Web/API/Pointer_events/Using_Pointer_Events)、[MDN 页面可见性](https://developer.mozilla.org/en-US/docs/Web/API/Document/visibilitychange_event)

战斗工具栏和暂停菜单提供“触控布局”。进入编辑器先暂停，编辑时控制器仅作位置预览；点击“完成”关闭编辑器后仍处于暂停状态，需要明确继续。可调整按键大小（44–76px）、透明度（35%–100%）、左右整组内移、底部距离、上键跳跃和特效档；支持恢复默认。这里调整的是左右按键组，不是逐个按键自由拖动。设置保存在 `elemental-clash-touch-layout-v1`，损坏或越界值会回到安全范围；存储不可用时仍可在本次界面调整。

## 标准与轻量特效

“标准特效”保持原绘制效果；“轻量特效”通过真实渲染路径关闭 Canvas 发光模糊、减少纯装饰粒子的绘制，并省略生存技能场的径向光晕。对战粒子以每三颗绘制一颗的方式抽样，模拟列表本身不变；敌人、敌方弹丸、经验球、角色和技能主体均保留。

两个档位都保持 **1280×720 Canvas backing store** 和固定 60Hz 战斗模拟。没有改为低分辨率渲染，没有删动画帧，也不改变碰撞、伤害、升级、随机数调用或时间流逝。回归使用相同输入与随机种子验证档位间战斗状态一致，并检查实际绘制日志中的发光与装饰粒子数量不同。设置只降低绘制工作量，不承诺特定设备的帧率或温升结果。

## 动画资源的生命周期

`acquireGameArt(characterIds, { legacy? })` 返回 `{ ready, release }`。对战和幸存者引擎在开局时获取本局角色的资源租约；重新开局先获取新租约，再释放旧租约，避免同角色复用时重复解码。销毁引擎时释放租约。动作预览显式使用 `legacy: true`，用于同屏对照新旧动作，切换角色或离开页面时释放。

- 大厅使用原有 `<img>` 展示立绘和背景，不再额外预解码五位角色的整套战斗素材。
- 成功加载新动作包时，只加载本局角色的新图集与 Canvas HUD／最终回退需要的立绘；旧动作和旧第二技能只在动作预览或新包失败时加载。
- 同一角色的并发使用者共享已加载资源，同一图集被多个片段引用时只解码一次；同角色镜像对战也只持有一份。
- 通用背景、元素效果和第二技能效果由全部活动租约共享；魈的专用下落特效只随魈的租约加载。
- 最后一个角色使用者释放时，移除角色图集、旧回退图、立绘和白闪画布的应用引用；最后一个游戏／预览使用者离开时，移除共享效果。浏览器自己的 HTTP 缓存仍可复用；垃圾回收与显存回收时间由浏览器决定。
- 加载结果必须匹配当前资源代次才能写回。加载期间退回大厅、快速切换角色或 React 开发模式重复挂载不会将旧资源重新放回缓存，也不会清除另一场仍在使用的资源。释放可重复调用。失败的新包在所有使用者释放后，可于下一次获取时重新尝试。

没有修改图片像素、动画帧、帧权重、战斗速度或伤害判定。当前策略控制跨角色和跨场次驻留；上场角色本身仍需完整图集的解码内存，受击时首次使用的白闪图会额外占用内存。设备端帧率、发热和长时间显存情况仍需真机验证。

## 回归与构建入口

`node scripts/art-regression.mjs` 保留全部 400 帧的双朝向绘制与注册验证，以及原有素材透明度、边缘留白等检查，并增加按需加载、共享租约、重复释放、预览并存、旧加载晚到、失败重试与提前销毁的回归覆盖。

```sh
node scripts/input-regression.mjs
node scripts/game-regression.mjs
node scripts/survival-regression.mjs
node scripts/clip-animation-regression.mjs
node scripts/art-regression.mjs
node scripts/visual-quality-regression.mjs
npm run build
git diff --check
```

资源生命周期的快速定向检查：

```sh
node scripts/art-regression.mjs 'art leases|animation preview|late decodes'
```

本轮已完成原美术回归 30 项、资源生命周期 5 项、动作片段回归 18 项、输入回归 9 项、对战回归 58 项和特效档回归 4 项，以及生存模式的定向输入／状态检查。生产构建 `npm run build` 已通过 TypeScript 与 Vite；Browserslist 数据库较旧提示不影响构建。完整十分钟生存回归仍可通过上面的独立命令执行，不能用定向检查替代真机持续运行验证。

## 浏览器验证范围

2026-10-10 的集成验证使用本机 Chromium 与 WebKit 的移动浏览器上下文，设置 `hasTouch: true`、`isMobile: true`。已完成以下检查：

- Chromium 844×390：多指移动＋普攻、触控取消、左右滑入上格不误跳、魈跳跃接元素坠击；默认 60px 按键与画面叠加布局正确。
- WebKit 390×844 → 844×390：竖屏期间战斗冻结，横持后必须明确继续；优菈战技的角色动作正常播放。
- Chromium 568×320：最大按键尺寸和偏移设置下，各键不越界、两组不重叠；生存模式自然战斗升至 2 级，升级弹窗期间计时冻结、触控键卸载，点选战技升级卡后成功继续。
- 两种模式：暂停面板进入布局编辑器时只有一个活动对话框；完成编辑后仍保持暂停。轻量特效选择会保留，恢复默认可用。单人试炼的触控跳跃、普攻和战技，以及移至顶部的 HUD 已检查。
- 桌面 1600×1100：自动模式未显示触控键，生存模式 D／W／J／I／Esc 正常；1440×1000 显式键盘模式的单人试炼保留原 HUD 与暂停行为。本机 Windows 的 `navigator.maxTouchPoints` 实际为 10，不能将这项描述为纯无触控硬件测试。
- Chromium 与 WebKit 的浏览器控制台均为 0 errors、0 warnings。独立架构审查通过，包含最终移动 HUD 的绘制复核。

这些检查属于浏览器引擎与触控事件仿真，**不是物理 iPhone／Android 真机测试**。实际设备的方向锁定权限、浏览器地址栏、系统手势、音频策略、温升、长时间帧率与内存峰值，仍需在对应硬件验证；当前没有物理手机性能结论。
